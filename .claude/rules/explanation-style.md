# 講解與回答的方式（2026-09-06 裁示，升自 feedback memory）

> 來源：a′_true 兩層文件的十幾輪來回。三次「我還是沒懂」都發生在換了一套符號（x̂₁、n_x、r）
> 或換了一個新詞重講同一件事；真正打通的是控制律那一行 code、一步四個數字的小表、
> 「估 n_w 錯多少 = 估 δw̄₁ 錯多少」這種一句話恆等式。

1. **順序固定**：一句白話答案 → 這個 repo 的具體東西（code 行 `file:line`、一個實際 run 的數字、
   一步一張小表）→ 推導。推導只在被問到時才給。
2. **只用專案符號**：δŵ̄₁、δŵ̄₃、y₁、y₂、n_w、e_δw̄₁、ℓ₁₁、P₁₁、R₁、λc、Δw̄_d、Δŵ̄、ā、ā′、ā″、b̂、
   a_nom、a_o、F_e、H。不引入通用 KF 符號（x̂、n_x、r、u）；聊天簡寫（Δ、B̂）要對回文件符號。
   新符號一律先走 derivation-workflow 第 12 條的四行，沒批准就每次寫全。
3. **先講角色與順序**：感測器／控制器／濾波器三個角色，一步之內誰先動、手上有什麼；
   再對到文件的節與行。一次只推一個概念。
4. **多層結構給機械拆法**，不給形容詞。例：「劃掉波浪號與 e₁ 項 = 層 1」。
5. **使用者說「沒懂」時**：不換符號、不換名詞重講。退回前一步找卡點（最常見兩個：
   「這個量濾波器手上有沒有」「這是無條件還是條件均值」），用同一套符號把那一步拆細。
6. **超過三個符號才講得清的概念，改舉數字例子**：取一個實際 run 的一步，nm 或 R 單位，列成小表。
7. **文件與對話分工**：`.tex` 只放式子，x[k+1] 在等號左邊、一行一式、代換分塊乘開、項標 (n)、
   不放數字、不放文字說明；解釋在對話裡做（derivation-workflow 第 10 條）。
8. **圖與 PDF 產完要 `open`**，對著頁碼講「這一頁看哪個方塊」（figure-style.md）。
