# 推導工作流規則

1. **無 trade-off 原則**：推導出來的東西不該有 trade-off。報「調 A 換 B」之前先問：
   兩個量是不是同一份推導決定的？是 → 推導還沒對，回去找錯，不要調參。
2. **內部參數洩漏 = 模型錯誤指紋**：內部參數（a_cov、a_pd、視窗長度）洩漏進結論，
   是比看圖可靠的錯誤偵測。驗收首選「參數不變性」測試（掃 10×，結果不准動）。
3. **修復必附驗收條件**：先寫判準再動手，不是「數字變好看」。
   既有判準範例：a_cov 不變性、P[0] 預算（E[(x̂∞−x̂₀)²] ≤ P[0]−P[∞]）、
   形狀驗收 sup|θ_eff−θ₀| ≲ √P[0]。
4. **兩步審視法**（「拆解推導／換角度審視」的操作型定義）：
   - 步驟一：概念 vs 推導/code —— 列出推導自己宣稱的前提，逐條對 code 核對
   - 步驟二：推導定義的量 vs 真實 log —— 從模擬 log 重建推導定義的量，對照觀測
   - 禁止以複述 memory 實驗編年史代替上述兩步
5. **參數 prior 設計**：照 `reference/shared/param_prior_rules.md`（三規則 + P[0] 六步鏈）。
   不要先調數字再找理由。

6. **因果宣稱必須有對手**（2026-08-12 使用者裁示，第 3 條的擴大：
   從「要動手修的時候」擴大到「所有解釋」）

   在複雜系統裡，說得通的機制永遠有好幾個；「我能構造出一個解釋」的先驗機率
   接近 1，所以**找到一個機制幾乎不帶資訊**——那通常只是最近想過的那個。

   任何因果宣稱一律用這一行講，寫不出來就不要講：

   ```
   [假說] X    對手 Y    分開它們：Z（成本 N 秒）
   ```

   - **成本要寫出來**。這個專案幾乎每個判別實驗都是 10 秒到 2 分鐘，寫出成本
     就等於自己否決「用斷言換 30 秒」。
   - **想不出對手 = 沒想夠**，不是放行的理由。回去想。
   - **標了 [假說] 的東西，在被量測之前不得出現在任何結論的推導鏈裡**。要用就
     降級成「若 X 成立則⋯」。08-12 最大的傷害不是講錯，是講錯的那句話變成了
     後面好幾層推理的地基。

   宣稱只有三種等級，沒有第四種：`[量到]`（附數字與 run）、`[推導]`（附方程式）、
   `[假說]`（附上面那一行）。

7. **儀器先驗證，再當證據**（同日）
   - 這個統計量會**消掉**什麼？（`std across seeds` 會消掉所有 seed 共有的
     確定性成分，不能拿來當誠實比）
   - 拿到的是**先驗還是後驗**？（Kalman 的 K_opt 公式要先驗；用後驗算出來的是
     `K_opt − K_filter`）
   - 這個旗標**真的有接線**嗎？先 grep。（`opts.y2_on` 曾經只改檔名與表頭，
     整輪 T2 因此作廢）
   - 抄來的公式**對回 SSOT**，不是對回最近那份 sibling；抄來的數字**重算一次**，
     不要用漸近式手算。

8. **新推導先獨立驗算，再開始寫 code**（同日）
   自己讀過太多次的方程式抓不到自己的錯：08-12 的獨立驗算抓到 3 個我抓不到的
   （性質的號、S7 漏項、從 sibling 繼承的 typo）。順序反過來做的代價是 controller
   帶著錯跑了一輪。

9. **判準用 seed 無關的簽名**（同日，限本專案的高散布架構）
   下結論一律用**配對差**（同 seed 同抽樣）與 seed 無關的簽名（漂移率、符號結構、
   誠實比）；報 mean 一定附 sd 與 SEM。RMS 被「重擲」主導：同一批資料，已知干擾臂
   的 RMS 是 t = 0.94（什麼都看不到），hold 漂移率是 t = −12.60（決定性）。
