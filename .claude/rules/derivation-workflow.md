# 推導工作流規則

1. **無 trade-off 原則**：推導出來的東西不該有 trade-off。報「調 A 換 B」之前先問：
   兩個量是不是同一份推導決定的？是 → 推導還沒對，回去找錯，不要調參。
2. **內部參數洩漏 = 模型錯誤指紋**：內部參數（a_cov、a_pd、視窗長度）洩漏進結論，
   是比看圖可靠的錯誤偵測。驗收首選「參數不變性」測試（掃 10×，結果不准動）。
3. **修復必附驗收條件**：先寫判準再動手，不是「數字變好看」。
   既有判準範例：a_cov 不變性、P[0] 預算（E[(x̂∞−x̂₀)²] ≤ P[0]−P[∞]）、
   形狀驗收 sup|θ_eff−θ₀| ≲ √P[0]。
4. **兩步審視法**（「拆解推導／換角度審視」的操作型定義）：
   - 步驟一：概念 vs 推導/code —— 列出推導自己宣稱的前提，逐條對 code 核對
   - 步驟二：推導定義的量 vs 真實 log —— 從模擬 log 重建推導定義的量，對照觀測
   - 禁止以複述 memory 實驗編年史代替上述兩步
5. **參數 prior 設計**：照 `reference/shared/param_prior_rules.md`（三規則 + P[0] 六步鏈）。
   不要先調數字再找理由。

6. **因果宣稱必須有對手**（2026-08-12 使用者裁示，第 3 條的擴大：
   從「要動手修的時候」擴大到「所有解釋」）

   在複雜系統裡，說得通的機制永遠有好幾個；「我能構造出一個解釋」的先驗機率
   接近 1，所以**找到一個機制幾乎不帶資訊**——那通常只是最近想過的那個。

   任何因果宣稱一律用這一行講，寫不出來就不要講：

   ```
   [假說] X    對手 Y    分開它們：Z（成本 N 秒）
   ```

   - **成本要寫出來**。這個專案幾乎每個判別實驗都是 10 秒到 2 分鐘，寫出成本
     就等於自己否決「用斷言換 30 秒」。
   - **想不出對手 = 沒想夠**，不是放行的理由。回去想。
   - **標了 [假說] 的東西，在被量測之前不得出現在任何結論的推導鏈裡**。要用就
     降級成「若 X 成立則⋯」。08-12 最大的傷害不是講錯，是講錯的那句話變成了
     後面好幾層推理的地基。

   宣稱只有三種等級，沒有第四種：`[量到]`（附數字與 run）、`[推導]`（附方程式）、
   `[假說]`（附上面那一行）。

7. **儀器先驗證，再當證據**（同日）
   - 這個統計量會**消掉**什麼？（`std across seeds` 會消掉所有 seed 共有的
     確定性成分，不能拿來當誠實比）
   - 拿到的是**先驗還是後驗**？（Kalman 的 K_opt 公式要先驗；用後驗算出來的是
     `K_opt − K_filter`）
   - 這個旗標**真的有接線**嗎？先 grep。（`opts.y2_on` 曾經只改檔名與表頭，
     整輪 T2 因此作廢）
   - 抄來的公式**對回 SSOT**，不是對回最近那份 sibling；抄來的數字**重算一次**，
     不要用漸近式手算。

8. **新推導先獨立驗算，再開始寫 code**（同日）
   自己讀過太多次的方程式抓不到自己的錯：08-12 的獨立驗算抓到 3 個我抓不到的
   （性質的號、S7 漏項、從 sibling 繼承的 typo）。順序反過來做的代價是 controller
   帶著錯跑了一輪。

9. **判準用 seed 無關的簽名**（同日，限本專案的高散布架構）
   下結論一律用**配對差**（同 seed 同抽樣）與 seed 無關的簽名（漂移率、符號結構、
   誠實比）；報 mean 一定附 sd 與 SEM。RMS 被「重擲」主導：同一批資料，已知干擾臂
   的 RMS 是 t = 0.94（什麼都看不到），hold 漂移率是 t = −12.60（決定性）。

10. **推導文件的排版規範**（2026-08-17）

    - 一份 `.tex` **只放方程**，散文一律另開 `_ref.tex`。例外僅三種：開頭的
      notation 括號、`(True − Estimator; …)` 這類一句話的座標說明、狀態向量後的
      `(d = 2)` 註記。
    - **所有狀態方程垂直堆疊、對齊在 `=`、一行一個。** 不用 `\qquad` 並排，
      不用 align 多欄把兩三個 state 擠在同一行。
    - **真動態與估測器逐行對應**：兩節的行順序必須一樣，讓「估測器 = 真動態
      拿掉未知項」用看的就成立，不必讀者自己比對。
    - **矩陣就寫成矩陣。** 放不下時只准動排版——格內折行（巢狀 `array`）、
      `\small`、加行距。**不准為了塞進頁寬而用縮寫符號把長式子包起來。**
    - **不包裝**：重複出現的長群組（例如 `Δw̄_d + (1−λc)δŵ̄₃`）每次完整寫出。
    - 節序固定九節：法則 → Jacobian → 真動態 → 狀態向量 → 估測器 → 誤差動態
      → 量測 → 雜訊 → Seed and prior（末節用 `\section*` 不編號）。
    - preamble 從 sibling **複製**，不重打。

11. **法則的開場必須蓋住兩端，不能只證遠場**（同日）

    只做遠場展開再消掉自變數，只證明了法則在遠場成立，對近壁什麼都沒說。
    正確的開場是三步：

    - 真值（多項式）；
    - **精確的自主法則**——真值單調 ⇒ 可反解 ⇒ 消掉自變數得 `ā′ = (1−ā)²/b_true(ā)`，
      這一步**沒有近似**，b_true 是函數不是常數；
    - **模型**：把 b_true(ā) 換成常數。這是唯一的近似，而且它現在無可爭議地
      只發生在這一行。

    兩端的極限值要寫出來（此處 `b_true(0) = 1`、`b_true(1) = 9/8`）。它們同時
    解釋了「兩個錨為什麼不一致」：b_true 是一條曲線，兩端讀數本來就不同，
    取哪一端是設計選擇不是矛盾。

12. **新符號與新概念先給人看，不直接寫進文件**（同日，使用者裁示）

    引入任何新符號或新概念之前，先用固定四行呈現，等回覆再動文件：

    ```
    符號         <symbol>
    是什麼       <物理量／診斷量／模型參數>
    為什麼需要   <哪一步非它不可>
    和既有的關係 <同名同義？不同物？既有文件叫什麼？>
    ```

    來源：`b_state` 曾被命名成一個文件裡根本不存在的 `b` 的衍生詞；
    `w̄₀` 與 `w̄_s` 曾把兩份文件分裂成兩套符號。兩次都是先決定了才給人看。

13. **儀器健全性檢查要在跑之前寫下來**（同日）

    每次跑新臂之前，先寫下「如果接線壞掉，哪個數字會露餡」，跑完先看那個，
    **不是先看 RMS**。08-13 三個 bug 全是「會跑完、數字看起來合理」的，
    全靠與內容無關的訊號抓到：

    - 設定值與印出值對不上（鎖定臂的 b̂ 該是 1.1396 卻印 1.0000）；
    - 兩個獨立臂的數字到小數點後兩位完全相同（獨立雜訊實現不可能）；
    - 基準臂必須**精確重現**已知數字（4.94），每次修完都要重驗。

    三層驗證各有盲點，不可互相取代：sympy 抓係數／級數／號但抓不到建模判斷；
    獨立 agent 抓漏項與「把截斷寫成等號」但它自己也會編機制；健全性檢查抓接線。
    agent 要求**逐項回報**並指定優先項——整份最後一次吐，斷線就全丟。
